為什麼需要

要同時看很多路直播，現在都怎麼看？

大多數單位不是沒解法，是解法太貴、太亂，或事後才發現漏掉了。

一、開十個分頁

十路直播十個分頁，聲音全部疊在一起，光是找「剛剛是哪一個在講話」就要一個一個點過去。想換版面就是重新排視窗。

二、堆硬體監看牆

一面牆要好幾台螢幕加訊號分割器，先花一筆錢，之後要換一路內容還得爬到機櫃後面接線。臨時加一路幾乎不可能。

三、事後回看錄影

當下沒盯到，只能靠截圖和事後回放補。突發狀況、對手動態、現場異常，錯過的那個當下追不回來。

核心能力

為「同時盯多路」這件事本身設計的細節

以下每一項都已實作在 Demo 頁面上，現在就能點開驗證。

音音訊獨佔

同一時間只有一路有聲音。點另一路的喇叭，前一路自動靜音 — 不必手動一格一格關掉，也不會有兩個人同時在講話。

格版面即時切換

2×2、3×3、4×4 一鍵切換，不必重新載入。任何一格都能單獨放到全螢幕，看清楚再切回整面牆。

序拖曳排序

抓著格子直接拖，把最需要盯的那一路挪到左上角。排好的順序會記住，下次開啟還是同一個位置。

省自動省資源

捲出畫面外的直播自動暫停，回到視野內再恢復。避免十幾個播放器同時全速運轉把機器拖垮。

診黑畫面自診

某一路不能播時，那一格會直接寫出原因和處理方式，而不是留一格黑的讓人猜。值班的人不用回頭問工程。

遷設定可搬家

整面牆的設定可匯出成一個 JSON 檔，換一台電腦匯入就完整還原。要複製同樣的版面到第二個場地，就是一個檔案的事。

導入方式

從直接拿去用，到完整客製

依照場域數量與維運需求，有三種不同深度的做法。

直接使用

純靜態網頁，丟到任何一個空間或起一個本機伺服器就能跑，沒有資料庫也沒有建置流程。貼上直播網址即可開始，設定存在瀏覽器裡。

白牌客製

換成自家品牌與配色、鎖定預設的直播清單、拿掉現場人員不該碰的操作按鈕，做成一開機就是正確畫面的專用版本。

專案導入

多個場域要從同一個後台派送版面、直播來源需要自動更新不必人工換網址、想知道哪一台裝置哪一路黑掉了 — 這些屬於客製開發範圍，可另行討論。

誠實說明

導入前請先確認

與其導入後才發現，不如先講清楚目前這個版本的適用範圍。

  1. 內容來源為 YouTube 官方嵌入播放器。小紅書與抖音的直播採簽章網址加來源鎖定，沒有公開的嵌入方式，無法放進第三方網頁 — 這是平台端的限制，不是本系統可以繞過的。
  2. 需要每一場直播各自的 watch?v= 網址。頻道網址（/@帳號、/channel/UC…）目前不適用，YouTube 已不支援「自動播出該頻道當前直播」的嵌入方式。直播結束換新場次時需更新網址；長期無人看管的場域建議搭配專案導入的自動更新機制。
  3. 需透過 http(s) 提供服務。直接雙擊 HTML 檔開啟會被 YouTube 拒絕播放（錯誤碼 153）。線上版本或本機伺服器都沒有這個問題。
  4. Demo 頁面上的觀看數與讚數為示意數字，依影片編號產生的固定假資料，非真實數據，正式導入時會移除或改接真實來源。
  5. 商用前請一併確認 YouTube 服務條款對嵌入播放器的規範，特別是關於在播放器周圍呈現商業內容的部分。
  6. Demo 中的品牌名稱為中性佔位，非任何實際企業。
